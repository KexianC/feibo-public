# 模型对话兜底与超级管理员通知

状态：2026-09-14 已随 `admin-monitor-fallback-20260914` 联合发布上线，两张通知表迁移及服务器／公网校验已通过。没有人为触发正式供应商故障；登录后的生产通知 UI 尚未通过现有会话验收。详见 `release/admin-monitor-fallback-20260914/上线验收说明.md`。

## 已实现行为

- 普通对话模型及腾讯智能体共用兜底入口。原模型同步报错、流式报错、返回空答案或连续 45 秒没有流事件时，尝试一次可用的 DeepSeek。超时可通过 `ai.chat.fallback.attempt-timeout-millis` 调整，属于流静默超时，整体 SSE 保留现有 3 分钟上限。
- DeepSeek 候选来自现有后台模型配置，必须是可见、未删除、已启用并具有有效凭据的叶子模型。优先普通模型，再按配置排序；原请求为普通模型时不能升级到高级模型。原模型本身是 DeepSeek 时不递归重试。
- 兜底保留原问题、系统提示与已选历史，不改变用户选择的模型。流式中途失败时发送 `model_fallback` 控制事件，前端清空本轮旧回答、思考内容与语音队列，再接收 DeepSeek 回答。
- 兜底也失败时，前端将 `error_message` 作为终止事件，清空未完成答案、停止语音与读取请求并显示安全错误；不会把错误文字拼入半截答案当作成功回答。
- 用户取消后关闭订阅；失效请求解析迟到不能继续调用原模型。兜底使用独立且有界的调度线程，避免被原模型的阻塞任务拖住。
- 内容校验与明确的敏感内容拒绝沿用原处理，不触发跨模型重试。会员额度仅按一个逻辑对话结算，控制事件不扣额度。
- 只保存最终成功答案的实际模型和原生 Token 快照，不将原模型失败尝试的用量混入 DeepSeek。未知费用继续保持未确认状态。
- 后台右上角增加超级管理员专属通知入口，展示原模型、错误类型、兜底模型、结果、时间与请求编号；支持未读数、分页、单条/全部已读，每位管理员分别保存已读状态。客户端隐藏与服务器路径、控制器、服务权限同时生效。
- 每个失败请求提交一条异步持久化通知，包含兜底成功、兜底失败、不可用、DeepSeek 自身失败或取消结果。不记录提问、回答、密钥或原始错误正文。通知存储失败或有界队列饱和时记录安全日志，不在聊天线程执行数据库写入；未入队或进程强制终止前尚未写入的事件可能丢失。

## 验证

- 63 项相关后端测试通过，覆盖同步/异步错误、空回答、45 秒超时、阻塞查询超时后恢复、上下文保留、用量隔离、取消、明确内容拒绝、双失败、禁止循环、候选资格、会员额度与数据库持久化及真实权限代理。
- 用户端执行 `npm run check:model-fallback`：运行真实发送处理函数，覆盖事件拆包、流末残留、旧内容替换、语音清理、长会话 ID、模型选择保留、首次即失败与主备模型双重失败。
- 管理端执行 `npm run check:model-failure-notices`：接口路径、鉴权请求与长 ID 验证。两个前端类型检查及生产构建通过，既有语音/模型 ID/角色身份/权限菜单检查通过。
- 本地浏览器以合成数据挂载真实通知组件，验证成功/失败状态、单条已读、全部已读、分页、空状态与加载失败提示。

Windows 下后端测试的 Java 临时目录指定到工作区 `.tmp/model-fallback-tests`，避免 Mockito 临时代理创建权限问题。前端构建使用工作区的实际路径 `D:\项目\飞驳`，避免桌面映射路径导致 Vite 别名解析问题。

## 部署顺序

1. 备份现有后端和两个前端工件。
2. 执行 `feibo_backend_master/docs/sql/model_failure_notifications_20260909.sql`，该脚本只创建通知及已读表，可重复执行。
3. 确认后台至少存在一个启用且凭据有效、资格符合原请求的 DeepSeek 模型。
4. 将用户端对 `model_fallback` 的支持与后端兜底逻辑作为同一批发布，并更新管理端通知入口。先在隔离环境模拟原模型故障，核验回答、真实持久化、管理员通知及普通管理员拒绝访问，再切换正式工件。
5. 回滚时恢复前一批后端及两个前端，保留新增通知表用于诊断。

通知接口与持久化细节见 `feibo_backend_master/docs/model-failure-notifications.md`。
