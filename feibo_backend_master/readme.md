# 数字医生项目交接文档

## 1. 项目概述

### 1.1 项目背景

数字医生项目是一个基于AI技术的医疗健康服务平台，提供智能问诊、健康咨询等服务。

### 1.2 项目定位

- **核心功能**：AI智能问诊、健康咨询、用户管理、数据统计等
- **技术定位**：采用微服务架构理念，基于Spring Boot构建的Java后端服务
- **用户群体**：普通用户、医疗专业人员

## 2. 技术栈

### 2.1 核心技术

| 技术类别 | 技术选型        | 版本 | 用途         |
| -------- | --------------- | ---- | ------------ |
| 基础框架 | Spring Boot     | 3.x  | 应用开发框架 |
| 持久层   | MyBatis-Plus    | -    | ORM框架      |
| 数据库   | MySQL           | -    | 关系型数据库 |
| 安全框架 | Spring Security | -    | 认证授权     |
| API文档  | Swagger/OpenAPI | 3.x  | API文档生成  |

### 2.2 外部服务

| 服务类别 | 服务名称   | 用途     |
| -------- | ---------- | -------- |
| 云存储   | 阿里云OSS  | 文件存储 |
| 短信服务 | 阿里云短信 | 短信发送 |
| AI模型   | DeepSeek   | 智能问诊 |
| AI模型   | Qwen       | 智能问答 |
| AI模型   | Baichuan   | 智能对话 |
| 支付服务 | 通联支付   | 在线支付 |

## 3. 项目结构

### 3.1 目录结构

```
java-backend/
├── digital-doctor-api/       # API接口定义层
├── digital-doctor-app/        # 应用启动层
├── digital-doctor-domain/     # 领域模型层 整个后台代码
├── digital-doctor-infrastructure/  # 基础设施层
├── digital-doctor-trigger/    # 触发器层
├── digital-doctor-types/      # 公共类型定义
├── docs/                      # 项目文档
└── pom.xml                    # 父项目依赖管理
```

### 3.2 模块职责

#### 3.2.1 digital-doctor-api

- **职责**：定义对外API接口
- **核心内容**：RESTful API接口定义、请求响应DTO

#### 3.2.2 digital-doctor-app

- **职责**：应用程序入口
- **核心内容**：Spring Boot启动类、全局配置、安全配置

#### 3.2.3 digital-doctor-domain

- **职责**：领域模型和业务逻辑 整个后台代码
- **核心内容**：实体类、业务服务、领域事件 后台业务逻辑代码

#### 3.2.4 digital-doctor-infrastructure

- **职责**：基础设施实现
- **核心内容**：数据库访问、外部服务集成、消息队列实现

#### 3.2.5 digital-doctor-trigger

- **职责**：定时任务和事件触发器
- **核心内容**：定时任务定义、事件监听器

#### 3.2.6 digital-doctor-types

- **职责**：公共类型定义
- **核心内容**：枚举类、通用工具类、常量定义

## 4. 核心架构设计

### 4.1 分层架构

```
┌─────────────────────────────────────────────────┐
│                 API接口层 (API)                 │
├─────────────────────────────────────────────────┤
│                应用服务层 (App)                 │
├─────────────────────────────────────────────────┤
│                领域模型层 (Domain)              │
├─────────────────────────────────────────────────┤
│              基础设施层 (Infrastructure)        │
└─────────────────────────────────────────────────┘
```

### 4.2 安全架构

- **认证机制**：JWT令牌认证
- **授权机制**：基于角色的访问控制(RBAC)
- **加密方式**：BCrypt密码加密
- **SSL配置**：SSL终结在Nginx层面，应用层仅处理HTTP请求

### 4.3 数据架构

- **主数据库**：MySQL，存储核心业务数据
- **文件存储**：阿里云OSS，存储图片、视频等大文件

## 5. 关键功能模块

### 5.1 用户管理模块

- **功能**：用户注册、登录、信息管理
- **核心类**：`UserService`、`AuthService`

### 5.2 AI问诊模块

- **核心类**：`OSSConfig`、`OSSAdminGateway`
- **存储服务**：阿里云OSS

### 5.4 支付模块

- **功能**：在线支付、支付回调处理
- **核心类**：`PaymentService`
- **支付渠道**：通联支付

## 6. 部署架构

### 6.1 部署环境

宝塔中部署项目，项目目录为`/www/wwwroot/digital-doctor-app.jar`

### 6.2 请求链路

```
用户请求 → SLB → Nginx → Spring Boot应用

token Bearer ...
用户指纹参数 Client-Fingerprint  test-device-001
幂等令牌  Idempotency-Token
```

### 6.3 SSL配置

- **配置位置**：Nginx层面
- **注意事项**：修改域名或SSL配置需调整Nginx

### 6.4 部署流程

1. 本地或CI/CD环境打包成JAR文件
2. 上传JAR包至`101.37.255.45`服务器的`/www/wwwroot`目录
3. 通过宝塔面板重启项目

## 8. 开发规范

### 8.1 代码规范

- 遵循Java编码规范
- 使用Lombok简化代码
- 接口定义清晰，参数验证完善

### 8.2 命名规范

- 类名：大驼峰命名法
- 方法名：小驼峰命名法
- 变量名：小驼峰命名法
- 常量名：全大写，下划线分隔

### 8.3 日志规范

- 使用SLF4J进行日志记录
- 日志级别：ERROR、WARN、INFO、DEBUG
- 关键操作必须记录日志

## 9. 监控与维护

### 9.1 日志管理

- **日志框架**：Logback
- **日志文件**：按日期和大小滚动存储
- **日志级别**：ERROR/INFO日志分离

### 9.2 异常处理

- **全局异常处理**：`GlobalExceptionHandler`统一处理未捕获异常
- **业务异常**：自定义业务异常类，明确错误类型

### 9.3 常见问题排查

- **数据库连接问题**：检查数据库配置和网络连接
- **AI模型调用失败**：检查API密钥和网络连接
- **文件上传失败**：检查OSS配置和文件大小限制
- **网站磁盘空间问题**：需定时清理日志文件，避免占用过多空间
- **网站日志问题**：可以通过宝塔中的日志管理功能查看和分析日志
