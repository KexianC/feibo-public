# 会员与额度账本

免费账户自动拥有普通模型无限对话、高级模型上海自然日 10 次、数字人视频累计 300 秒、AI 视频累计 60 秒。视频免费额度不会按天刷新。`ADMIN`、`SUPER_ADMIN`（兼容 `SUPERADMIN`）、`ORG_ADMIN` 在启用状态下不限额度；权益配置接口仅允许超级管理员。

## 数据与业务约定

- `t_entitlement_policy` 保存免费权益，修改免费配额只改变可用上限，不清空已使用记录。
- `t_entitlement_product_config` 使用原会员/充值表的业务 ID，与支付订单引用相同的商品。只有明确配置、已启用、价格大于零的商品对用户开放购买。零价会员可由超级管理员定向发放。
- `t_entitlement_grant` 保存支付或人工发放的不可变权益快照、原因、操作人、有效期。修改商品配置适用于后续购买和发放，已有权益依照原快照履约。同会员续费顺延期限；新增时长当即到账，在对应延长期限届满时到期。
- `t_entitlement_bucket` 区分免费、按日赠送、充值、会员、历史迁移的余额批次。高级对话先使用当天额度，再使用额外次数；其余批次优先使用即将过期的余额。
- 同时拥有多个会员或定向日额度时，高级模型每日上限取免费和有效权益中的最高值；`-1` 表示高级模型不限次数。额外对话次数、视频秒数按批次相加。
- DATETIME 中参与额度有效期计算的时间统一存 UTC。高级模型的自然日通过 `Asia/Shanghai` 计算后转为 UTC 存储。返回接口的有效期带 UTC 时区。

每次预占、发放、结算均持有 `t_entitlement_account` 中当前用户的行锁。`reserve` 持久化业务键和预占分配；`resize` 调整实际秒数；`commit` 将预占变为消费；`release` 退还预占。重复业务键不得改变资源或原申请量；已释放的请求不可重新提交或结算。已成功结算的任务不会因迟到的失败回调获得退款。停用账号不得发起新消费，但已受理任务的结算、退款、到账仍可完成。

视频生产请求结果不确定时保留预占，不通过计时器自动释放，避免供应商实际上已接受任务时产生免费消费。已确认失败由业务回调或管理员的有审计记录的核销流程处理。

## 接口

用户接口 `GET /api/v1/entitlements/me` 和 `GET /api/v1/entitlements/catalogue` 使用 `code: "0000", info, data` 格式。后台 `/api/admin/entitlements` 使用 `code: 200, msg, data` 格式，所有修改写入操作审计。

后台支持 `/config`、`/free-plan`、`/plans`、`/packs`、`/models/{modelId}`、`/accounts/{userId}`、`/accounts/{userId}/grants`。发放请求的 `requestId` 应在每一次用户确认发放时生成，网络重试沿用同一值。相同请求即使商品后来下架或改价，也返回已发放结果；相同编号改变原始请求内容会被拒绝。

`IEntitlementService.snapshotProduct` 只产生可购买商品的服务端快照；订单保存快照与价格。验证支付成功后，在同一个数据库事务内完成订单状态更新和 `grantPaidOrder`。不得按支付回调时的最新商品权益发放。

## 数据迁移与发布

1. 备份数据库并停止旧版本所有消费入口、视频提交、回调、支付任务；不得同时运行新旧扣额逻辑。
2. 执行 `docs/sql/platform_entitlements_20260909.sql`。模型默认普通由持久化迁移标识保护，重复运行不会覆盖管理员后续调整。
3. 审核并执行 `docs/sql/platform_entitlements_legacy_20260909.sql`。核实历史时间字段类型及所存时区，设置 `@legacy_entitlement_timezone`；来源列为 TIMESTAMP 时，会话 `time_zone` 必须与该偏移一致，脚本发现不匹配会中止。旧数字人扣费代码按分钟，充值包元数据却存在“100 分钟 = 6000 余额”的冲突，必须对照实际商品、订单和余额确认单位，再设置 `@legacy_digital_seconds_per_unit` 为 1（秒）或 60（分钟）。未设置、异常余额、无效资源类型、缺失业务 ID、孤儿账户或未知资源模板会中止，不能跳过核对后直接上线。
4. 同时执行订单快照迁移及视频预占业务键迁移，再启用新版本。历史已支付余额按原批次与经核实的倍率保留，高级对话原次数保持不变；有效付费会员的名称和期限也迁移。
5. 记录迁移前后批次数与金额/额度合计。通过超级管理员配置付费会员及充值包，再验证下单、已付款重复通知、成功消费、失败退款和逐账户余额。

原资源表保留以供核对。新版本产生消费后，不能直接切回旧扣额逻辑，因为旧表不会自动同步新的消费与到账。回退必须先停写并按新账本核对、迁回增量，或在尚未开放新消费之前恢复升级前备份。

测试包括 `EntitlementServiceTest` 的真实 H2 MySQL 模式 SQL、并发消费和事务回滚，以及 `TradeRepositoryProductSnapshotTest` 的购买快照边界。生产 MySQL 的存储过程与历史实际数据迁移须在发布前按备份环境另行验证。
